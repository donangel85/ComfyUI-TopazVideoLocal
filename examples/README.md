# Example workflows

Load any of these with **Workflow → Open** in ComfyUI. Each one carries a note on the
canvas explaining what it shows, so the graph is self-contained.

## Start here for video

`07_video_upscale.json` is the graph this pack was built for. Video is what Topaz Video
AI does, and what these nodes are for; the still-image examples are the same graphs with
something quicker to load.

```
Load Video → Get Video Components → Topaz Video Upscale → Create Video → Save Video
                    │  fps ──────────────────^                 ^   ^
                    │  audio ──────────────────────────────────┘   │
                    └──fps ────────────────────────────────────────┘
```

| File | Shows |
|---|---|
| `07_video_upscale.json` | A whole clip through Topaz. Audio goes around the outside and is put back at the end; `fps` comes off the clip rather than being typed twice. **For most work the only thing to change is the preset.** |
| `08_video_interpolate.json` | 24 → 48 fps. `output_fps` drives *Create Video*, so the running time is unchanged instead of the clip playing at half speed. |
| `09_video_restore_chain.json` | Deinterlace → stabilise → enlarge, in that order, with a note on why the order matters and why unused passes should be bypassed rather than left in. |

`Load Video`, `Get Video Components`, `Create Video` and `Save Video` are **ComfyUI's own
nodes** — nothing extra to install. If you already use Video Helper Suite, its loader and
*Video Combine* drop into the same places.

## The still-image examples

Every Topaz node takes a plain IMAGE batch and does not care where the frames came from,
so these are the identical graphs with a picture on the front. Pick your own image in the
`LoadImage` node before running — the stored filename is a placeholder and ComfyUI will
say so if it is not in your input folder.

| File | Shows |
|---|---|
| `01_basic_upscale.json` | The smallest useful graph: 2× with Proteus. Start here. |
| `02_output_resolution.json` | **Topaz Resolution** driving an exact output size, with `fit_mode` deciding what happens when the aspect ratio does not match. |
| `03_divisible_by_32.json` | The same, constrained to multiples of 32 — what latent video models need. Full HD comes out as 1920×1088. |
| `04_multi_pass_chain.json` | Two models in one ffmpeg call: repair on the first pass, detail on the second, each with its own parameters. |
| `05_presets_and_tuning.json` | Profiles, and the sliders you adjust them with. Engine Settings attached with `verbose` on so the ffmpeg command lands in the log. |
| `06_restore.json` | Deinterlace, motion deblur and stabilisation side by side on the same source. |

## How these files are kept honest

They are generated by `research/make_examples.py` from the nodes' live definitions rather
than written by hand, because a workflow stores widget values as a **positional** array:
a hand-written example goes wrong the moment a node gains a widget, and goes wrong
silently, since nothing reads these files until somebody loads one.

They are also opened in ComfyUI and arranged by hand, which is why regenerating carries
each node's position, size and title over from the file on disk. Only values, wiring and
node membership come from the generator.

The generator itself is a maintainer's tool and lives outside the package, so it is not
in this repository. What *is* here is `tests/test_examples.py`, which makes the same
comparison as part of the normal test suite — widget counts, combo membership, numeric
ranges, link endpoints, and that no third-party node has crept in. A node change that
would break a saved graph fails a test rather than surfacing as a confusing error in
somebody's browser.

```bash
python -m pytest tests/test_examples.py -q
```

## Where this fits in an AI video chain

The case these nodes were built for: a generated clip is small and soft, and the model
that comes next only accepts certain dimensions.

```
MiniMax-H3  ──▶  Topaz Video Upscale  ──▶  LTX 2.5
                       ▲
        Topaz Resolution (divisible_by = 32)
```

`03_divisible_by_32.json` is that middle section, with `LoadImage` and `SaveImage` where
the two AI models attach. Swap them for:

- **In:** the node your generator decodes to images — `MiniMax H3 Decode AV` in
  `ComfyUI-MiniMaxH3`, or the equivalent in whichever pack you use.
- **Out:** the node the next model takes images from.

The examples deliberately ship without those nodes wired in. Their widget layouts belong
to packs this repository cannot verify against, and a workflow carrying guessed values
fails at load with an error pointing at the wrong place. The Topaz half is correct and
tested; connect your own two ends.

**The one thing to get right** is `divisible_by`. MiniMax-H3 needs multiples of 32, which
is why Full HD is 1920×1088 there and not 1920×1080. A mismatch does not fail in the
Topaz node — it fails later, inside the model, as a tensor-shape error that reads as if
something else is wrong.
