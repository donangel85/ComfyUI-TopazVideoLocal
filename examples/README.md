# Example workflows

Load any of these with **Workflow → Open** in ComfyUI.

Each one starts from `LoadImage`, so pick your own picture in that node before running —
the stored filename is a placeholder and ComfyUI will say so if it is not in your input
folder. For video, replace `LoadImage` with whatever loader you already use (Video Helper
Suite's `Load Video`, for instance); every Topaz node here takes a plain IMAGE batch and
does not care where it came from.

| File | Shows |
|---|---|
| `01_basic_upscale.json` | The smallest useful graph: 2x with Proteus. Start here. |
| `02_output_resolution.json` | **Topaz Resolution** driving an exact output size, with `fit_mode` deciding what happens when the aspect ratio does not match. |
| `03_divisible_by_32.json` | The same, constrained to multiples of 32 — what latent video models need. Full HD comes out as 1920x1088. |
| `04_multi_pass_chain.json` | Two models in one ffmpeg call: repair on the first pass, detail on the second, each with its own parameters. |
| `05_presets_and_tuning.json` | Profiles, and the sliders you adjust them with. Engine Settings attached with `verbose` on so the ffmpeg command lands in the log. |
| `06_restore.json` | Deinterlace, motion deblur and stabilisation side by side on the same source. |

These are generated by `research/make_examples.py` from the nodes' live definitions
rather than written by hand, so the widget values cannot drift out of order when a node
changes. Regenerate them after touching any node's `INPUT_TYPES`.

## Where this fits in an AI video chain

The case these nodes were built for: a generated clip is small and soft, and the model
that comes next only accepts certain dimensions.

```
MiniMax-H3  ──▶  Topaz Video Upscale  ──▶  LTX 2.5
                       ▲
        Topaz Resolution (divisible_by = 32)
```

`03_divisible_by_32.json` is that middle section, with `LoadImage` and `SaveImage` where
the two AI models attach. Swap them for:

- **In:** the node your generator decodes to images — `MiniMax H3 Decode AV` in
  `ComfyUI-MiniMaxH3`, or the equivalent in whichever pack you use.
- **Out:** the node the next model takes images from.

The example deliberately ships without those nodes wired in. Their widget layouts belong
to packs this repository cannot verify against, and a workflow carrying guessed values
fails at load with an error pointing at the wrong place. The Topaz half is correct and
tested; connect your own two ends.

**The one thing to get right** is `divisible_by`. MiniMax-H3 needs multiples of 32, which
is why Full HD is 1920x1088 there and not 1920x1080. A mismatch does not fail in the
Topaz node — it fails later, inside the model, as a tensor-shape error that reads as if
something else is wrong.
